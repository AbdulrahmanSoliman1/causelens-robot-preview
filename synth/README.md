# Blocked-action benchmark (`synth/`)

Can an image model show what happens when an action **can't** work (the device is unplugged, the container is empty, the
fuel is missing)? This folder holds the benchmark behind the main README's numbers.

## Setup

- `make.py`: scenarios written by Muse Spark (a device, an action, and the one condition that blocks it), each with a
  blocked and a working camera picture generated by Muse Image. A scenario is kept only if Muse Spark confirms the
  blocking condition in both pictures. 25 scenarios form the held-out set.
- Every after-image was labelled **by eye, blind to which method made it**: did the expected outcome happen, and was
  the blocking condition kept? Labels and keys are in `heldout_labels.json` / `heldout_key.json`, `ablate_labels*.json` /
  `ablate_key*.json` and `audit*_labels.json` / `audit*_key.json`.

## Results (25 held-out scenarios, blind by eye)

| Muse Image is given | Blocked action drawn right | Working action drawn right |
|---|---|---|
| the action only (plain Muse Image) | **1/25** (in 15/25 it changed the blocking cause: plugged it in, added fuel) | 25/25 |
| the action + the blocking fact ("the plug is not in any outlet") | 2/25 | 24/24 |
| the action + the computed outcome (what CauseLens sends) | **24/25** | **24/25** |

- **Plain Muse Image draws the usual result.** It almost never shows a blocked action correctly, and most of the time it
  quietly changes the scene to make the action work.
- **Telling it the cause is not enough; telling it the outcome is.** With the outcome stated, the drawing is right 48/50
  across blocked and working scenes. That's why CauseLens computes the outcome with `do()` first and writes it into the prompt.

## Files

- `make.py`: scenarios, camera pictures and the edit arms. `score.py`: judging and the labelling page.
- `ablate.py`: the prompt comparison above (action only, + cause, + outcome).
- `diagnose.py`, `robust_test.py`: analysis of the scene-reading step that led to `causal/robust.py` and then
  `causal/open.py`.
- Generated images (`out/`) aren't in the repository; the scripts that make them are.
